💡 Phân Hệ Evaluation Hoạt Động Như Thế Nào?

Hình dung đơn giản như một kỳ thi kiểm định chất lượng tự động cho mỗi kỹ năng AI

Mô Hình Dễ Hiểu
1. Phiếu Chấm Điểm (Rubric)
Tương tự như đáp án chấm thi. Quy định sẵn: Bài làm bắt buộc phải có những phần nào? Có bị lỗi cấm kỵ không? Đạt từ bao nhiêu điểm trở lên thì được công nhận đạt chuẩn (PASS).
File tương ứng: evaluation.yaml
2. Đề Thi & Bài Mẫu (Benchmark)
Một đề bài thực tế kèm 2 bài làm mẫu: Một bài làm tốt để máy kiểm tra xem có đạt điểm cao không, và một bài làm lỗi cố tình để máy chứng minh khả năng bắt lỗi.
Thư mục tương ứng: benchmarks/
3. Giám Thị Chấm Điểm (Runner)
Bộ công cụ chấm tự động trong tích tắc. Lấy bài làm đối chiếu với phiếu chấm, tính ra điểm số (0 - 100), thông báo PASS hay FAIL và ghi nhận vào bảng theo dõi tuần.
Lệnh chạy: npm run eval
Giá Trị Mang Lại
Xóa bỏ hoàn toàn việc tranh cãi cảm tính ("tôi thấy prompt này hay / dở"). Cả Repo Owner và Thành viên đều có chung một thước đo định lượng khách quan để nghiệm thu chất lượng công việc.

Mục tiêu: Tận dụng các AI skills trong công việc hằng ngày (phân tích tài liệu, vẽ kiến trúc, chia task...) và tự tin rằng output tạo ra luôn đạt chuẩn trước khi bàn giao.
Trách nhiệm & Thao tác:

Mục tiêu: Nắm chắc bức tranh sức khỏe của cả 20 skills, ngăn ngừa tình trạng sửa skill này làm hỏng skill khác (chống hồi quy khi merge PR).
Trách nhiệm & Thao tác:

• Định kỳ hàng tuần: Xuất báo cáo HTML (npm run report) để họp giao ban và xem skill nào cần hỗ trợ.
• Khi duyệt PR: Kiểm tra xem skill mới có đủ rubric và benchmark đạt chuẩn hay không.
Lệnh chính cần nhớ:
npm run server • npm run report

Quy Chế Chấm Điểm

🎯 Cách Tính PASS Hoặc FAIL Theo Benchmark

Trực quan hóa phễu thẩm định 3 tầng và cơ chế đối chiếu kép giữa mẫu chuẩn và mẫu lỗi

Thuật Toán Chấm Điểm
Tầng 1: Kiểm Tra Cấu Trúc Chốt Chặn
1. Các mục bắt buộc: Kiểm tra tài liệu có đủ các phần thiết yếu theo quy định rubric.

2. Lỗi cấm kỵ (Instant Fail): Nếu phát hiện lỗi nghiêm trọng (như rò rỉ mã code vào tài liệu kinh doanh) thì bài làm bị đánh trượt ngay lập tức, bất kể điểm số các phần khác cao bao nhiêu.
Tầng 2: Điểm Số 4 Chiều Trọng Số
Điểm tổng hợp (0 - 100) được tính từ 4 khía cạnh nghiệp vụ:
• Độ đầy đủ (25-30%): Bao quát các kịch bản.
• Độ chặt chẽ (35%): Logic kinh doanh đúng.
• Chuẩn nghiệm thu (20-25%): Đúng format Gherkin/Traceability.
• Định dạng (15%): Trình bày rõ ràng.
Tầng 3: Ngưỡng Đạt Benchmark Nghiệm Thu
Ngưỡng đỗ: Điểm tổng ≥ 80/100.

Cơ chế đối chiếu kép trong Benchmark:
• sample_good_output: Mẫu chuẩn phải đạt PASS (≥80đ).
• sample_flawed_output: Mẫu lỗi cố tình bắt buộc phải bị bắt FAIL (<80đ) để chứng minh máy chấm có độ nhạy!
Chỉ số Rework (Cần sửa lại): Khi bài làm bị FAIL hoặc có điểm từ 80 đến 84 điểm, hệ thống sẽ gắn nhãn cảnh báo cần tối ưu thêm (Rework Required) để người dùng tinh chỉnh output đạt chất lượng hoàn hảo.
Minh bạch 100%: Mọi điểm số và nhãn kết quả đều truy vết được nguồn gốc quy tắc Trang 6 / 11

❓ Các Tình Huống Thường Gặp & Cách Xử Lý (FAQ)

Giải đáp nhanh các vướng mắc phổ biến nhất của cả Thành viên và Repo Owner

Hỏi Đáp Nhanh
1. Thành viên: Tại sao bài làm tốt (Good Output) của tôi bị báo FAIL?
Nguyên nhân: Có thể bạn viết thiếu một đề mục bắt buộc được quy định trong file evaluation.yaml, hoặc nội dung bài mẫu quá ngắn (dưới 50 ký tự).
Cách sửa: Nhìn vào dòng lỗi màu vàng trên terminal, bổ sung đúng tiêu đề mục đó vào bài mẫu là sẽ đạt ngay.
2. Thành viên: Chạy lệnh bị báo lỗi "Connection Refused"?
Nguyên nhân: Bạn chạy lệnh có đuôi :send nhưng trạm server chưa được bật.
Cách sửa: Nếu chỉ muốn test cá nhân, chỉ cần gõ lệnh offline: npm run eval <tên-skill> (không có chữ :send).
3. Thành viên: Chạy kiểm tra có tốn phí token AI không?
Hoàn toàn không tốn phí: Bộ đánh giá dùng thuật toán kiểm tra cấu trúc và ngữ nghĩa offline siêu tốc, chạy trực tiếp trên máy bạn mà không cần gọi API trả phí ra ngoài.
4. Repo Owner: Dữ liệu của team có bị rò rỉ ra ngoài không?
Bảo mật 100%: Trạm đo lường chạy nội bộ trên máy bạn. Dữ liệu chỉ ghi nhận điểm số và mã lỗi kỹ thuật, tuyệt đối không lưu trữ nội dung prompt bí mật hay thông tin của khách hàng.
Gặp khó khăn? Liên hệ ngay Repo Owner để được hướng dẫn trực tiếp Trang 10 / 11

📌 Phụ Lục: Các Lệnh Mở Rộng & Cờ Tùy Biến

Bảng tra cứu đầy đủ các lệnh nâng cao và cờ tham số dành cho người cần tùy biến sâu

Dành Cho Tham Khảo
1. Danh Mục Các Lệnh Mở Rộng
Lệnh Thực Thi Mô Tả Chức Năng
npm run eval:send Kiểm tra 1 skill và gửi số liệu về server.
npm run eval:all Quét toàn bộ 20 kỹ năng trong kho offline.
npm run eval:all:send Quét cả 20 kỹ năng và đồng bộ lên server.
npm run test:e2e Chạy kiểm thử end-to-end từ test đến xuất báo cáo.
2. Các Cờ Tùy Biến (CLI Flags)
Cờ Tham Số Mục Đích Sử Dụng
--opt-in Bật gửi telemetry lên máy chủ đo lường.
--benchmark=<tên> Chỉ chạy duy nhất 1 file test case cụ thể.
--server-url=<url> Trỏ đến server từ xa (mặc định: port 3456).
--all Chế độ chạy hàng loạt cho tất cả kỹ năng.

Gợi ý: Trong công việc hằng ngày, bạn chỉ cần dùng lệnh chính npm run eval <tên-skill>. Hãy tham khảo trang Phụ Lục này khi cần tự động hóa nâng cao hoặc cấu hình CI/CD!
